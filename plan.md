# LINKEDINIFY™ — Build Plan (plan.md)

> **Repo:** https://github.com/Thushar070/Linkify.git
> **Goal:** Build the full Linkedinify agentic web app, phase by phase, with real working code at the end of every phase — not one giant dump at the end.
> **Agent executing this plan (Antigravity):** follow phases strictly in order. Do not skip ahead. Do not start Phase N+1 until Phase N is committed and working.

---

## 0. HOW TO USE THIS PLAN (read first)

1. Work through phases **in order**: Phase 0 → Phase 8.
2. Each phase has a **Definition of Done** checklist. Do not move to the next phase until every box is checked.
3. **Commit after every meaningful change**, not just at the end of a phase. See §1 "Git & Commit Rules" — this is mandatory, not optional.
4. Every commit message must be **short, human-written, plain English** — no AI-sounding fluff, no emojis in commit messages, no "Generated by AI" text.
5. After finishing each phase, push to the repo and update the `CHANGELOG.md` (Phase 1 creates it).
6. If a phase is too big, break it into smaller commits — small, frequent commits are preferred over one large commit per phase.

## 1. GIT & COMMIT RULES (mandatory, apply for the entire project)

**Repo:** `https://github.com/Thushar070/Linkify.git`

### Commit frequency
- Commit **every time you**: add a feature, remove something, fix a bug, refactor, tweak styling, or update copy/text.
- Do **not** batch unrelated changes into one commit.
- Aim for many small commits over the course of the build — reviewers should be able to see the app being built step by step through the commit history.

### Commit message style
Write commit messages the way a human developer would — short, direct, lowercase-first-word is fine, no periods at the end, no marketing language, no emoji.

Use these prefixes consistently:

| Prefix | When to use | Example |
|---|---|---|
| `added` | new feature / new file / new component | `added bullshit level selector` |
| `fixed` | bug fix | `fixed emoji count showing wrong number` |
| `removed` | deleted code/feature/file | `removed unused toast component` |
| `enhanced` | improved existing feature, no new feature | `enhanced reality check card spacing` |
| `refactor` | code cleanup, no behavior change | `refactor agent pipeline into separate functions` |
| `style` | pure CSS/UI tweaks | `style adjusted post card shadow` |
| `docs` | README/plan/changelog updates | `docs updated changelog for phase 2` |

**Good examples:**
```
added copy button to generated post
fixed inflation percentage calculation
removed placeholder lorem ipsum text
enhanced loading state animation
added CEO mode toggle
fixed hashtag generator duplicating tags
style matched LinkedIn card border radius
added reality check reveal animation
```

**Bad examples (do not do this):**
```
Update files
✨ Added amazing new feature! 🚀
Commit
Fixed stuff
Generated commit via AI assistant
```

### Branching
- Work directly on `main` unless a phase explicitly says otherwise (this is a small solo project — no need for over-engineering with branches).
- Push after every commit so the remote always reflects current progress.

### After every phase
- Update `CHANGELOG.md` with a short section for that phase (bullet list of what shipped).
- Tag the commit that completes a phase, e.g. `git tag phase-2-complete`.

## 2. DESIGN DIRECTION (read before writing any UI code)

This is the single most important non-functional requirement. **Do not produce generic "AI app" UI.**

### Hard rules
- **Strictly no purple, violet, or blue** anywhere — not in buttons, gradients, links, icons, focus rings, or charts. This includes indigo, lavender, periwinkle, and any blue-purple gradient (the classic "AI startup" gradient is banned).
- No generic centered-card-on-gradient-background layout. No glowing blobs. No glassmorphism-for-the-sake-of-it. No stock "AI sparkle" icon.
- No default shadcn purple/violet theme. If shadcn is used, the theme must be recolored.

### Go for a LinkedIn-native feel
- Base palette inspired by LinkedIn's real UI: off-white/light-gray background (`#F4F2EE`-ish), white cards, near-black text (`#000000DE` / `#191919`), LinkedIn-blue is banned so substitute the "action" accent with **LinkedIn-adjacent but distinct** colors — go with:
  - Primary accent: a **warm amber/gold** (`#E8A33D`-ish) or **teal/green** (`#0A6E4E`-ish) — pick ONE as the single accent color and use it sparingly.
  - Success/positive: green.
  - Warning/BS-meter/danger: red/orange (for the "corporate BS score" bar).
  - Neutrals: true grays, not blue-tinted grays.
- Typography: use a clean system/sans stack similar to LinkedIn (e.g. `-apple-system, "Segoe UI", Helvetica, Arial, sans-serif`). Avoid quirky display fonts.
- Cards should genuinely resemble a LinkedIn post card: rounded corners (small radius, ~8px not 24px), subtle 1px border or soft shadow, avatar circle placeholder, name/headline row, reaction icons row (👍❤️💡) at the bottom, comment/share/repost icons — even if non-functional, they sell the illusion.
- Buttons: LinkedIn-style pill/rounded-rect outline buttons, not gradient-filled "AI SaaS" buttons.
- Micro-interactions are welcome (hover states, subtle transitions) but tasteful — no bouncy over-the-top animation.
- Reference `/mnt/skills/public/frontend-design/SKILL.md`-style thinking: intentional, distinctive, not templated defaults.

### Definition of "no AI slop"
- No lorem-ipsum-looking layout.
- No mismatched icon set (pick one icon library — `lucide-react` — and stick to it).
- No inconsistent spacing/padding across components.
- Every screen should look like it was designed, not scaffolded.
